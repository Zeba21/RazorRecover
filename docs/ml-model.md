# XGBoost ML Model & SHAP Explainability

## 1. Overview

RazorRecover uses an **XGBoost Classifier** (`xgboost.XGBClassifier`) to evaluate failed subscription payment cases and calculate the mathematical probability of successful recovery ($P_{recovery} \in [0.0, 1.0]$).

The prediction output is augmented by a **SHAP (SHapley Additive exPlanations)** layer that decomposes the prediction score into feature-level positive and negative attributions, yielding human-readable explanations.

---

## 2. Feature Schema & Inputs (13 Features)

The ML pipeline processes 13 engineered features derived from customer payment history, invoice metadata, and failure context:

| Feature Name | Data Type | Range / Options | Description |
| :--- | :--- | :--- | :--- |
| `transaction_amount` | Float | $\ge 0.0$ | Payment transaction amount in INR |
| `customer_payment_history` | Integer | $\ge 0$ | Total count of historical payments made by customer |
| `previous_success_rate` | Float | $0.0 - 1.0$ | Proportion of successful past payments |
| `previous_failure_count` | Integer | $\ge 0$ | Total count of past failed payment attempts |
| `retry_count` | Integer | $\ge 0$ | Number of recovery retries already attempted for case |
| `customer_age_days` | Integer | $\ge 0$ | Tenure of customer account in days |
| `time_since_failure` | Float | $\ge 0.0$ | Time elapsed since initial payment failure (hours) |
| `invoice_age` | Float | $\ge 0.0$ | Age of unpaid invoice in days |
| `previous_recovery_success` | Integer | $0 \text{ or } 1$ | Flag indicating prior successful recovery experience |
| `failure_type` | String | Categorical | Failure classification (`insufficient_funds`, `authentication_failed`, `gateway_timeout`, `card_expired`, `network_error`) |
| `subscription_status` | String | Categorical | Subscription state (`active`, `past_due`, `trialing`, `canceled`, `unpaid`, `paused`) |
| `payment_method` | String | Categorical | Payment instrument (`card`, `upi`, `netbanking`, `wallet`) |
| `customer_segment` | String | Categorical | Customer tier (`starter`, `regular`, `enterprise`, `vip`) |

## 3. Risk Level Mapping Logic

The AI service applies deterministic risk mapping based on the predicted **Recovery Probability** ($P_{recovery}$):

$$
\text{Risk Level} = \begin{cases}
\mathbf{LOW} & \text{if } P_{recovery} \ge 0.70 \quad (\text{High recovery chance } \ge 70\%) \\
\mathbf{MEDIUM} & \text{if } 0.40 \le P_{recovery} < 0.70 \quad (\text{Moderate recovery chance } 40\%-69\%) \\
\mathbf{HIGH} & \text{if } P_{recovery} < 0.40 \quad (\text{Low recovery chance } < 40\%)
\end{cases}
$$

> 💡 **Clarification on Terminology**:
> - **$P_{recovery}$** measures the chance that the payment can be recovered.
> - **Risk Level** measures the **Risk of Revenue Loss**. Therefore, a high recovery probability ($P_{recovery} \ge 0.70$) corresponds to a **LOW Risk Level** (low risk of loss).

## 4. Model Training Pipeline & Verified Metrics

### 4.1 Training Dataset
The model was trained on a 12,000-sample synthetic SaaS billing dataset generated by `ai-service/generate_data.py`. The dataset was partitioned into:
- **Train Set**: 8,400 samples (70%)
- **Validation Set**: 1,800 samples (15%)
- **Test Set**: 1,800 samples (15%)

### 4.2 Hyperparameters
- `n_estimators`: 150
- `max_depth`: 4
- `learning_rate`: 0.05
- `subsample`: 0.8
- `colsample_bytree`: 0.8
- `eval_metric`: `logloss`
- `random_state`: 42

### 4.3 Verified Model Evaluation Metrics
Evaluated on the 1,800-sample unseen test set (stored in `ai-service/models/model_metadata.json`):

| Metric | Verified Score |

| **Precision** | **83.29%** (`0.8329`) |
| **Recall** | **96.77%** (`0.9677`) |

## 5. SHAP Explainability Engine

The SHAP explainability module (`ai-service/explain_model.py`) uses `shap.TreeExplainer` to calculate local feature attributions:

1. **Feature Attribution**: Computes baseline expected value ($E[f(x)]$) and individual feature contributions ($\phi_i$).
2. **Ranking**: Sorts features into:
   - **Positive Factors**: Features pushing $P_{recovery}$ higher (e.g. `previous_success_rate = 0.95`, `subscription_status = active`).
   - **Negative Factors**: Features pulling $P_{recovery}$ lower (e.g. `retry_count = 2`, `invoice_age = 14`).
3. **Narrative Generation**: Constructs human-readable explanations (e.g., *"High customer payment success rate (+18.4% impact) and active subscription status increase recovery probability."*).
